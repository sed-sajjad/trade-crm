# نصب، دسترسی و نگه‌داری

## نصب

1. از دیتابیس و فایل‌های وردپرس نسخه پشتیبان بگیرید.
2. ZIP افزونه `trade-crm` را از مسیر افزونه‌ها در پیشخوان نصب و فعال کنید.
3. ساختار فعلی پیوندهای یکتای سایت را تغییر ندهید. مسیر `/crm/` باید از طریق تنظیمات موجود وب‌سرور به وردپرس برسد؛ اگر ۴۰۴ بود، ابتدا تنظیمات مسیرها را در محیط آزمایشی بررسی کنید. افزونه قوانین داخلی خودش را ثبت می‌کند و فایل `.htaccess` را بازنویسی نمی‌کند. نیازی به ساخت برگه CRM در المنتور نیست.
4. در کاربران وردپرس برای هر همکار حساب شخصی بسازید و نقش «سرپرست CRM» را انتخاب کنید. مدیر وردپرس نیز به CRM دسترسی دارد.
5. HTTPS معتبر را برای دامنه فعال کنید.

فعال‌سازی پنج جدول InnoDB را با پیشوند واقعی WordPress می‌سازد. مهاجرت با `dbDelta` و نسخه schema انجام می‌شود. ارتقای نسخه ۱٫۱٫۰ ساختار حوزه‌های تخت را به درخت سه‌سطحی تبدیل می‌کند، شناسه و ارتباط‌های موجود را حفظ می‌کند و ۲۵ دسته اصلی با زیر‌دسته‌های پیش‌فرض می‌افزاید. برای تغییر ساختار دیتابیس پیش از ارتقا نسخه پشتیبان بگیرید. غیرفعال‌کردن و حذف افزونه داده‌های CRM را حذف نمی‌کند؛ افزونه مسیر حذف دائمی داده‌ها ندارد.

## نصب PWA

- در iPhone، نشانی CRM را با Safari باز کنید، Share و سپس Add to Home Screen را بزنید. گزینه Open as Web App را روشن بگذارید.
- در Android، نشانی CRM را در Chrome باز کنید و از منو Install app یا Add to Home screen را انتخاب کنید.

این برنامه به اینترنت و HTTPS نیاز دارد. Service Worker فقط فایل‌های عمومی برنامه، قلم و آیکون‌ها را می‌گیرد. پاسخ API، HTML دارای nonce، صفحه ورود و اطلاعات مخاطب cache نمی‌شوند. ثبت آفلاین و Push در این نسخه وجود ندارد. اگر صفحه هنگام قطع اتصال باز بماند، متن فرم فقط در حافظه همان صفحه می‌ماند.

## نقش‌ها و ورود

سرپرست فقط قابلیت `manage_trade_crm` و خواندن عمومی وردپرس را می‌گیرد؛ مجوز نصب افزونه یا مدیریت حساب‌ها ندارد. ساخت، تغییر رمز و لغو دسترسی همکاران از پیشخوان توسط مدیر وردپرس انجام می‌شود. API در هر درخواست قابلیت را دوباره بررسی می‌کند.

ورود و بازیابی رمز از صفحه استاندارد WordPress استفاده می‌کنند. بازیابی رمز از راه ایمیل زمانی کار می‌کند که ارسال ایمیل در سرور وردپرس تنظیم شده باشد. ثبت‌نام عمومی فعال نمی‌شود.

صفحه اصلی دست‌نخورده می‌ماند و کاربران از سایر بخش‌های پیشخوان به CRM هدایت نمی‌شوند. سورس فعلی ظاهر ورود و بازیابی رمز را ساده‌تر می‌کند؛ قلم وزیرمتن محلی است و استایل ورود فقط در `wp-login.php` بارگذاری می‌شود. فرم‌ها، پیام‌های خطا، بازیابی رمز و مقصد ورود از سازوکار استاندارد وردپرس استفاده می‌کنند. پس از ورود از آدرس `/crm/` به برنامه دسترسی داشته باشید. مهاجرت و تنظیم نقش‌ها فقط هنگام فعال‌سازی یا ارتقای مدیریتی اجرا می‌شوند؛ در درخواست بازدیدکنندگان عمومی اجرا نمی‌شوند.

## کش و سئو در سایت موجود

خروجی CRM و API آن هدرهای `no-store` و `noindex` دارند؛ مقصد ورود مهمان و خطای دسترسی نیز خصوصی هستند. CSS و JavaScript برنامه فقط در صفحه CRM بارگذاری می‌شوند. PWA و Service Worker به `/crm/` محدودند و نام کش هر نصب مستقل است. افزونه گزینه نمایش به موتورهای جست‌وجو، canonical و robots صفحات عمومی را تغییر نمی‌دهد.

در کش/CDN سایت، `/crm`، `/crm/` و `/wp-json/trade-crm/` و شکل `?rest_route=/trade-crm/…` را از کش HTML/API مستثنا کنید. در LiteSpeed Cache افزونه درخواست خصوصی را با API رسمی `litespeed_control_set_nocache` نیز اعلام می‌کند؛ کش بالادستی که پیش از اجرای PHP پاسخ می‌دهد باید جداگانه تنظیم شود. فقط کش مسیرهای CRM را پس از تغییر پاک کنید. برای این کار کش کل سایت را خاموش نکنید و robots.txt یا گزینه جلوگیری از ایندکس‌شدن کل سایت را تغییر ندهید.

برای نصب نهایی روی magicamoghaddam.com، دستورالعمل `DEPLOYMENT-magicamoghaddam.fa.md` را دنبال کنید.

## مدل داده

جدول‌های افزونه:

- `wp_trade_crm_contacts`: مشخصات مخاطب، مسئول، وضعیت، موعد پیگیری، توضیح اولیه، زمان‌ها و version.
- `wp_trade_crm_contact_numbers`: شماره E.164 و کاربرد تماس/واتساپ؛ شماره در همه پرونده‌های فعال و بایگانی‌شده یکتا است.
- `wp_trade_crm_industries`: عنوان حوزه، دسته مادر، وضعیت فعال و کلید پایدار برای داده پیش‌فرض.
- `wp_trade_crm_contact_industries`: رابطه چندبه‌چند مخاطب و حوزه.
- `wp_trade_crm_activities`: یادداشت و سابقه افزایشی با نام تاریخی نویسنده و شناسه درخواست.

`wp_` در این نام نمونه است. پیشوند واقعی همان پیشوند نصب WordPress خواهد بود. اطلاعات کاربران و تنظیمات کلی برنامه در جدول‌ها و APIهای خود WordPress می‌مانند.

فهرست پیش‌فرض شامل ۲۵ دسته اصلی در کالا و خدمات است و شاخه‌های پرکاربرد مانند «مواد غذایی و نوشیدنی ← خشکبار و آجیل ← پسته» را تا سه سطح دارد. مدیر CRM می‌تواند عنوان، والد و وضعیت را تغییر دهد یا حوزه تازه بسازد. نام تکراری در یک والد مجاز نیست؛ همین نام زیر والد دیگر مجاز است. غیرفعال‌کردن دسته مادر، انتخاب تازه زیرشاخه‌ها را متوقف می‌کند و ارتباط‌های قبلی مخاطبان را نگه می‌دارد. حذف دائمی فقط برای مورد بدون زیر‌دسته و بدون ارتباط مخاطب ممکن است. به‌روزرسانی افزونه عنوان و وضعیت دسته‌های پیش‌فرض را به حالت اولیه برنمی‌گرداند.

## پشتیبان‌گیری و بازیابی

از کل دیتابیس WordPress نسخه پشتیبان بگیرید؛ پنج جدول CRM هم در همین نسخه قرار می‌گیرند. پیش از هر ارتقای افزونه یا schema، پشتیبان را بسازید و امکان بازیابی آن را بررسی کنید. بازیابی یک جدول به‌تنهایی ممکن است ارتباط چندبه‌چند یا سابقه را ناقص کند؛ بازیابی هماهنگ هر پنج جدول توصیه می‌شود.

## ساخت از سورس

در پوشه `wp-content/plugins/trade-crm`:

```powershell
composer install
pnpm install --frozen-lockfile
pnpm test
composer test
pnpm build
composer install --no-dev --prefer-dist --classmap-authoritative
```

خروجی PHP در `vendor/` و رابط ساخته‌شده در `assets/build/` قرار می‌گیرد. برای ساخت ZIP، کل پوشه افزونه با این دو زیرپوشه و فایل‌های مستنداتش بسته‌بندی شود؛ روی هاست Node.js یا Composer لازم نیست.
