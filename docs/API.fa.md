# راهنمای API افزونه CRM بازرگان

ریشه API برابر `wp-json/trade-crm/v1/` است و با تابع‌های استاندارد وردپرس در مسیر فعلی نصب ساخته می‌شود. تمام endpointهای این سند خصوصی هستند و به نشست معتبر وردپرس، nonce معتبر در `X-WP-Nonce` و قابلیت `manage_trade_crm` نیاز دارند. پاسخ‌های خصوصی با `Cache-Control: private, no-store` ارسال می‌شوند.

## قالب پاسخ خطا

وردپرس خطا را به‌شکل `{ code, message, data }` برمی‌گرداند. `data.status` کد HTTP است. خطای فیلدها `data.field` دارد؛ تعارض شماره، پرونده موجود را در `data.contact` می‌دهد و تعارض ویرایش `data.current` را برای بازبینی نسخه فعلی برمی‌گرداند.

| وضعیت | کاربرد |
|---|---|
| 400 | ورودی یا فیلد نامعتبر |
| 401 | نشست ورود وجود ندارد |
| 403 | nonce نامعتبر یا دسترسی CRM وجود ندارد |
| 404 | مخاطب یا حوزه پیدا نشد |
| 409 | شماره تکراری، نسخه قدیمی، عملیات ناسازگار یا شناسه درخواست با محتوای دیگر |
| 500 | خطای ذخیره‌سازی عمومی؛ جزئیات فنی فقط در log سرور ثبت می‌شود |

## مسیرها

| روش و مسیر | کاربرد |
|---|---|
| `GET /bootstrap` | گزینه‌های فرم، کاربر فعلی، سرپرستان فعال، وضعیت‌ها، منبع‌ها، تنظیمات، شهرها و کدهای کشور قابل استفاده برای شماره |
| `GET /dashboard` | آمار مخاطبان و موعدهای امروز و عقب‌افتاده به وقت تهران |
| `GET /contacts` | فهرست صفحه‌بندی‌شده؛ پارامترهای `q`, `status`, `assigned_user_id`, `country`, `city`, `industry_id`, `followup`, `archive`, `limit`, `cursor` |
| `POST /contacts` | ساخت مخاطب؛ هدر `X-Trade-CRM-Request-ID` یا `request_id` یکتا الزامی است |
| `GET /contacts/{id}` | پرونده مخاطب، شماره‌ها و حوزه‌ها |
| `PATCH /contacts/{id}` | ویرایش با `version` خوانده‌شده از پرونده |
| `GET /contacts/{id}/activities` | رویدادهای پرونده با `limit` و `before_id` |
| `POST /contacts/{id}/notes` | افزودن یادداشت متن ساده؛ شناسه درخواست یکتا الزامی است |
| `POST /contacts/{id}/followup/complete` | تکمیل پیگیری، ثبت نتیجه و انتخاب موعد بعدی؛ شناسه درخواست یکتا و `version` الزامی است |
| `POST /contacts/{id}/archive` | بایگانی با `version` |
| `POST /contacts/{id}/restore` | بازیابی با `version` |
| `GET /industries` | جست‌وجو و صفحه‌بندی فهرست درختی؛ پارامترهای `q`, `parent_id`, `scope=all|selectable`, `limit`, `cursor` |
| `POST /industries` | افزودن حوزه؛ بدنه `{ "name": "پسته", "parent_id": 22 }`؛ والد صفر برای دسته اصلی |
| `GET /industries/{id}` | اطلاعات حوزه، مسیر کامل، وضعیت انتخاب‌پذیری و امکان حذف |
| `PATCH /industries/{id}` | تغییر عنوان، والد یا فعال‌بودن؛ بدنه می‌تواند شامل `name`, `parent_id`, `is_active` باشد |
| `DELETE /industries/{id}` | حذف دائمی فقط وقتی حوزه بدون زیر‌دسته و بدون مخاطب باشد؛ وگرنه 409 |
| `GET /settings` | تنظیمات برنامه |
| `PATCH /settings` | تغییر نام مجموعه، نام برنامه و کشور پیش‌فرض شماره |

## بدنه مخاطب

نمونه ساخت مخاطب:

```json
{
  "name": "علی رضایی",
  "first_name": "علی",
  "last_name": "رضایی",
  "company": "بازرگانی نمونه",
  "phone": "۰۹۱۲۱۲۳۴۵۶۷",
  "whatsapp": "09121234567",
  "whatsapp_same_as_phone": true,
  "country_code": "IR",
  "city": "تهران",
  "industry_ids": [2, 5],
  "source": "referral",
  "status": "new",
  "assigned_user_id": 14,
  "followup_at": "2026-10-13T06:15:00.000Z",
  "followup_topic": "ارسال کاتالوگ",
  "initial_note": "در نمایشگاه با ما آشنا شد."
}
```

نام اجباری است و دست‌کم یکی از تماس یا واتساپ باید ارسال شود. شماره‌ها در سرور با libphonenumber اعتبارسنجی، به E.164 تبدیل و در دیتابیس یکتا می‌شوند. شماره تماس و واتساپ یکسان در یک پرونده فقط یک ردیف شماره خواهند داشت. تاریخ API با منطقه زمانی مشخص ارسال می‌شود و پاسخ تاریخ‌ها UTC با پسوند `Z` است؛ مقدارهای ذخیره‌شده در دیتابیس UTC هستند.

`status` فقط یکی از `new`, `following_up`, `customer`, `closed` است. `followup` در فهرست می‌تواند `today`, `overdue`, `has`, یا `none` باشد. `archive` برابر `active`, `archived`, یا `all` است. تعداد هر صفحه حداکثر ۱۰۰ است.

فهرست حوزه‌ها حداکثر سه سطح دارد و پاسخ هر مورد شامل `id`, `parent_id`, `name`, `path`, `path_label`, `depth`, `is_active`, `is_selectable`, `child_count`, `contact_count`, `can_delete` است. `is_selectable` فعال‌بودن خود مورد و والدهایش را در نظر می‌گیرد. جست‌وجو نام هر سطح و مسیر کامل را با نرمال‌سازی حروف فارسی/عربی پیدا می‌کند. `parent_id=0` فقط دسته‌های اصلی را می‌دهد؛ در نبود `parent_id` جست‌وجو در همه سطح‌ها انجام می‌شود. `cursor` شناسه عددی آخرین مورد است و پاسخ `next_cursor` دارد.

فیلتر مخاطب با `industry_id`، دسته انتخاب‌شده و همه زیر‌دسته‌هایش را شامل می‌کند. انتساب تازه به حوزه غیرفعال با پاسخ 400 رد می‌شود؛ ارتباط قبلی آن در ویرایش مخاطب حفظ می‌شود. تلاش برای حذف حوزه دارای مخاطب یا زیر‌دسته، با `trade_crm_industry_in_use` و وضعیت 409 پاسخ می‌گیرد.

## تعارض و درخواست تکراری

هر ویرایش باید نسخه دریافتی از پرونده را بفرستد. نسخه قدیمی پاسخ 409 می‌گیرد و نسخه فعلی را در `data.current` دریافت می‌کند. ایجاد مخاطب، ثبت یادداشت و تکمیل پیگیری، شناسه UUID درخواست دارند؛ تکرار همان شناسه با محتوای یکسان نتیجه قبلی را برمی‌گرداند و استفاده از آن برای محتوای دیگر پاسخ 409 می‌دهد.
