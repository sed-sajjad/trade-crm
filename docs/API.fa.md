# راهنمای API افزونه CRM بازرگان

ریشه API برابر `wp-json/trade-crm/v1/` است و با تابع‌های استاندارد وردپرس در مسیر فعلی نصب ساخته می‌شود. تمام endpointهای REST این سند خصوصی هستند و به نشست معتبر وردپرس، nonce معتبر در `X-WP-Nonce` و قابلیت `manage_trade_crm` نیاز دارند. پاسخ‌های خصوصی با `Cache-Control: private, no-store` ارسال می‌شوند.

## بازیابی توکن نشست در نسخهٔ ۱٫۲٫۳

پیکربندی صفحه، `sessionUrl` را به `wp-admin/admin-ajax.php?action=trade_crm_session` همان نصب تنظیم می‌کند. این مسیر فقط خواندنی است، کوکی ورود معتبر و قابلیت `manage_trade_crm` می‌خواهد و `{ user_id, nonce, logout_url }` برمی‌گرداند. مهمان ۴۰۱ و کاربر بدون دسترسی ۴۰۳ می‌گیرد. پاسخ private/no-store است و کوکی یا نشست تازه ایجاد نمی‌کند. برای تازه‌کردن nonce منقضی، این مسیر به nonce قبلی نیاز ندارد؛ احراز هویت توسط کوکی استاندارد وردپرس انجام می‌شود.

کلاینت در بازگشت به صفحه و پس از خطای `rest_cookie_invalid_nonce` توکن تازه می‌گیرد. درخواست ردشده در لایهٔ nonce حداکثر یک بار، با همان بدنه و شناسهٔ درخواست تکرار می‌شود و فقط وقتی `user_id` با کاربر اولیهٔ صفحه برابر باشد. خطای شبکه یا ۵۰۰ موجب تکرار خودکار نوشتن نمی‌شود. توکن‌های عادی پاسخ REST نیز از هدر `X-WP-Nonce` خوانده می‌شوند.

## قالب پاسخ خطا

وردپرس خطا را به‌شکل `{ code, message, data }` برمی‌گرداند. `data.status` کد HTTP است. خطای فیلدها `data.field` دارد؛ تعارض شماره، پرونده موجود را در `data.contact` می‌دهد و تعارض ویرایش `data.current` را برای بازبینی نسخه فعلی برمی‌گرداند.

| وضعیت | کاربرد |
|---|---|
| 400 | ورودی یا فیلد نامعتبر |
| 401 | نشست ورود وجود ندارد |
| 403 | nonce نامعتبر یا دسترسی CRM وجود ندارد |
| 404 | مخاطب یا حوزه پیدا نشد |
| 409 | شماره تکراری، نسخه قدیمی، عملیات ناسازگار یا شناسه درخواست با محتوای دیگر |
| 500 | خطای ذخیره‌سازی عمومی؛ جزئیات فنی فقط در log سرور ثبت می‌شود |

## مسیرها

| روش و مسیر | کاربرد |
|---|---|
| `GET /bootstrap` | گزینه‌های فرم، کاربر فعلی، سرپرستان فعال، وضعیت‌ها، منبع‌ها، تنظیمات، شهرها و کدهای کشور قابل استفاده برای شماره |
| `GET /dashboard` | آمار مخاطبان و موعدهای امروز و عقب‌افتاده به وقت تهران |
| `GET /contacts` | فهرست صفحه‌بندی‌شده؛ پارامترهای `q`, `status`, `assigned_user_id`, `country`, `city`, `industry_id`, `followup`, `archive`, `limit`, `cursor` |
| `POST /contacts` | ساخت مخاطب؛ هدر `X-Trade-CRM-Request-ID` یا `request_id` یکتا الزامی است |
| `GET /contacts/{id}` | پرونده مخاطب، شماره‌ها و حوزه‌ها |
| `PATCH /contacts/{id}` | ویرایش با `version` خوانده‌شده از پرونده |
| `GET /contacts/{id}/activities` | رویدادهای پرونده با `limit` و `before_id` |
| `POST /contacts/{id}/notes` | افزودن یادداشت متن ساده؛ شناسه درخواست یکتا الزامی است |
| `POST /contacts/{id}/followup/complete` | تکمیل پیگیری، ثبت نتیجه و انتخاب موعد بعدی؛ شناسه درخواست یکتا و `version` الزامی است |
| `POST /contacts/{id}/archive` | بایگانی با `version` |
| `POST /contacts/{id}/restore` | بازیابی با `version` |
| `GET /industries` | جست‌وجو و صفحه‌بندی فهرست درختی؛ پارامترهای `q`, `parent_id`, `scope=all|selectable`, `limit`, `cursor` |
| `POST /industries` | افزودن حوزه؛ بدنه `{ "name": "پسته", "parent_id": 22 }`؛ والد صفر برای دسته اصلی |
| `GET /industries/{id}` | اطلاعات حوزه، مسیر کامل، وضعیت انتخاب‌پذیری و امکان حذف |
| `PATCH /industries/{id}` | تغییر عنوان، والد یا فعال‌بودن؛ بدنه می‌تواند شامل `name`, `parent_id`, `is_active` باشد |
| `DELETE /industries/{id}` | حذف دائمی فقط وقتی حوزه بدون زیر‌دسته و بدون مخاطب باشد؛ وگرنه 409 |
| `GET /settings` | تنظیمات برنامه |
| `PATCH /settings` | تغییر نام مجموعه، نام برنامه و کشور پیش‌فرض شماره |

## بدنه مخاطب

نمونه ساخت مخاطب:

```json
{
  "first_name": "علی",
  "last_name": "رضایی",
  "company": "بازرگانی نمونه",
  "website": "https://example.com",
  "phone": "۰۹۱۲۱۲۳۴۵۶۷",
  "whatsapp": "09121234567",
  "whatsapp_same_as_phone": true,
  "country_code": "IR",
  "city": "تهران",
  "industry_ids": [2, 5],
  "source": "referral",
  "status": "new",
  "assigned_user_id": 14,
  "followup_at": "2026-10-13T06:15:00.000Z",
  "followup_topic": "ارسال کاتالوگ",
  "initial_note": "در نمایشگاه با ما آشنا شد."
}
```

`first_name` و `last_name`، دست‌کم یکی از تماس یا واتساپ و حداقل یک شناسهٔ معتبر در `industry_ids` اجباری‌اند. عنوان `name` در پاسخ، از ترکیب نام و نام خانوادگی ساخته می‌شود و مقدار ارسالی `name` در درخواست نادیده گرفته می‌شود. هر بخش نام حداکثر ۱۰۰ و عنوان ترکیبی حداکثر ۱۹۰ نویسه است. شماره‌ها در سرور با libphonenumber اعتبارسنجی، به E.164 تبدیل و در دیتابیس یکتا می‌شوند. شماره تماس و واتساپ یکسان در یک پرونده فقط یک ردیف شماره خواهند داشت. تاریخ API با منطقه زمانی مشخص ارسال می‌شود و پاسخ تاریخ‌ها UTC با پسوند `Z` است؛ مقدارهای ذخیره‌شده در دیتابیس UTC هستند.

`website` اختیاری است و حداکثر ۲۰۴۸ نویسه دارد. فقط آدرس‌های `http` و `https` پذیرفته می‌شوند؛ آدرس بدون پیشوند مانند `example.com` با `https://` ذخیره می‌شود. مقدار خالی، آدرس قبلی را پاک می‌کند؛ حذف این فیلد از درخواست ویرایش، آدرس قبلی را حفظ می‌کند. آدرس سایت در پاسخ پرونده و جست‌وجوی مخاطبان نیز در دسترس است.

`status` فقط یکی از `new`, `following_up`, `potential_customer` (مشتری احتمالی), `customer`, `closed` است. `followup` در فهرست می‌تواند `today`, `overdue`, `has`, یا `none` باشد. `archive` برابر `active`, `archived`, یا `all` است. تعداد هر صفحه حداکثر ۱۰۰ است.

فهرست حوزه‌ها حداکثر سه سطح دارد و پاسخ هر مورد شامل `id`, `parent_id`, `name`, `path`, `path_label`, `depth`, `is_active`, `is_selectable`, `child_count`, `contact_count`, `can_delete` است. `is_selectable` فعال‌بودن خود مورد و والدهایش را در نظر می‌گیرد. جست‌وجو نام هر سطح و مسیر کامل را با نرمال‌سازی حروف فارسی/عربی پیدا می‌کند. `parent_id=0` فقط دسته‌های اصلی را می‌دهد؛ در نبود `parent_id` جست‌وجو در همه سطح‌ها انجام می‌شود. `cursor` شناسه عددی آخرین مورد است و پاسخ `next_cursor` دارد.

فیلتر مخاطب با `industry_id`، دسته انتخاب‌شده و همه زیر‌دسته‌هایش را شامل می‌کند. انتساب تازه به حوزه غیرفعال با پاسخ 400 رد می‌شود؛ ارتباط قبلی آن در ویرایش مخاطب حفظ می‌شود. تلاش برای حذف حوزه دارای مخاطب یا زیر‌دسته، با `trade_crm_industry_in_use` و وضعیت 409 پاسخ می‌گیرد.

## فهرست پیش‌فرض نسخهٔ ۲

نسخهٔ ۱٫۲٫۰ همان قرارداد حوزه‌ها و `industry_ids` را حفظ می‌کند. فهرست پیش‌فرض نسخهٔ ۲ شامل ۵۴۷ مورد است؛ همهٔ صفحه‌ها از `GET /industries` با `next_cursor` قابل دریافت‌اند. مثلاً `GET /industries?q=کیوی&scope=selectable` مسیر کامل کیوی را برمی‌گرداند و املای عربی `كيوي` نیز پشتیبانی می‌شود. شناسهٔ عددی هر حوزه وابسته به نصب است؛ آن را از پاسخ API بگیرید.

تعریف‌های فهرست در `data/industry-catalog.json` رکوردهای دارای `key`، `parent_key` و `name` هستند. کلیدها شناسه‌های ثابت داخلی ورود داده‌اند و جایگزین `id` در API نیستند. نسخهٔ `trade_crm_industry_catalog_version`، نقشهٔ `trade_crm_industry_seeded_keys` و گزارش `trade_crm_industry_catalog_report` در Options نگه‌داری می‌شوند. ورود فهرست در فعال‌سازی و `admin_init` مدیر اجرا می‌شود؛ عملیات API یا بازکردن فرم، فهرست را بازسازی نمی‌کند.

## تعارض و درخواست تکراری

هر ویرایش باید نسخه دریافتی از پرونده را بفرستد. نسخه قدیمی پاسخ 409 می‌گیرد و نسخه فعلی را در `data.current` دریافت می‌کند. ایجاد مخاطب، ثبت یادداشت و تکمیل پیگیری، شناسه UUID درخواست دارند؛ تکرار همان شناسه با محتوای یکسان نتیجه قبلی را برمی‌گرداند و استفاده از آن برای محتوای دیگر پاسخ 409 می‌دهد.
